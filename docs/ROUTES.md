# Pulse — карта адресов

Все адреса приложения: страницы фронтенда, API, Django-админка и служебные пути. Подробности
решений — в [`README.md`](../README.md), полное описание API — Swagger `/api/docs`.

**Где открывать** (после `make up`):

| | Локально | Через ngrok (`make tunnel`) |
|---|---|---|
| Фронтенд | http://localhost:8080 | `https://<поддомен>.ngrok-free.app` |
| API, Swagger, админка | http://localhost:8080 (через nginx) или http://localhost:8000 напрямую | тот же адрес ngrok |

Демо-аккаунт: `demo@pulse.app` / `DemoPulse2026!`. Администратор (Django-админка):
`admin@pulse.app` / `AdminPulse2026!`.

## Фронтенд (React)

### Публичные страницы — без входа

| Путь | Страница |
|---|---|
| `/login` | **Вход.** Email и пароль; ошибки у полей. С `?reason=expired` — плашка «Сессия истекла»; после входа возвращает на `?redirect=` (только внутренние пути). Вошедшего пользователя перенаправляет на `/`. |
| `/register` | **Регистрация.** Email, пароль, повтор пароля; правила пароля в подсказке, ошибки сервера (занятый email, слабый пароль) — у полей. |
| `/status/{slug}` | **Публичная статус-страница** (без шапки приложения). Баннер «Все системы работают / Частичный сбой / Серьёзный сбой», список сервисов: статус, uptime за 24 часа и 30 дней. Без URL мониторов и внутренних данных. Обновляется раз в минуту. Демо: `/status/demo`. |

### Страницы приложения — после входа

Шапка: логотип, разделы «Мониторы / Статус-страницы / Полигон», email, тема, выход.
Без сессии любой путь ведёт на `/login`.

| Путь | Страница |
|---|---|
| `/` | **Дашборд.** Карточки мониторов: цветной статус, последнее время ответа (или причина сбоя: «Код 503», «Таймаут»…), uptime за 24 часа, время проверки, мини-график за сутки (сбои — красным на оси времени). Проблемные — первыми. Фильтр по статусу в URL (`/?status=DOWN`), счётчик «N из 20», кнопка «Добавить монитор». Обновляется сам каждые 15 с. |
| `/monitors/new` | **Новый монитор.** Название, URL, HTTP-метод, интервал, таймаут, диапазон ожидаемого кода, проверка содержимого («содержит строку», «валидный JSON»), флаги «Проверять» и «Публичный». Ошибки backend (в т.ч. SSRF, лимит 20) — у полей. |
| `/monitors/{id}` | **Страница монитора.** Статус и параметры; кнопки «Изменить», «Пауза/Возобновить», «Удалить» (с подтверждением). График времени ответа с переключателем 24h / 7d / 30d (`?period=`), uptime, средний ответ, p95, число инцидентов, полоса доступности по интервалам. Инциденты («Идёт сейчас» / «Решён», длительность, причина, «Показать ещё»). Последние проверки с пагинацией (`?page=`) и причиной каждого сбоя. Обновляется каждые 15 с. |
| `/monitors/{id}/edit` | **Изменение монитора** — та же форма, заполненная текущими значениями. |
| `/status-pages` | **Статус-страницы.** Список своих страниц (до 5): название, публичная ссылка, число мониторов; изменить, удалить. |
| `/status-pages/new` | **Новая статус-страница.** Название, адрес (предлагается из названия), выбор мониторов — только публичных. |
| `/status-pages/{id}/edit` | **Изменение статус-страницы.** |
| `/playground` | **Полигон.** 8 тестовых эндпоинтов: адрес (копируется), текущий режим, что он делает и как должна отреагировать система, кнопки переключения режима. |

Любой другой путь — «Страница не найдена». Чужой или несуществующий монитор/страница — тоже
«не найдена».

## API — `/api/v1`

Ответы — JSON. Ошибки в одном формате: `{"error": {"code", "message", "fields"?}}`.
Авторизация — заголовок `Authorization: Bearer <access>`. «Вход» — нужен токен.

### Авторизация

| Метод и путь | Доступ | Что делает |
|---|---|---|
| `POST /api/v1/auth/register` | все | Регистрация; сразу выдаёт пару токенов. `201` / `422` |
| `POST /api/v1/auth/login` | все | Вход по email и паролю. `200` / `401` |
| `POST /api/v1/auth/refresh` | все | Новая пара токенов по refresh; старый refresh отзывается. `200` / `401` |
| `POST /api/v1/auth/logout` | вход | Отзывает refresh-токен. `204` |
| `GET /api/v1/auth/me` | вход | Текущий пользователь |

Ограничение частоты для `/auth/*` — 20 запросов в минуту с IP.

### Мониторы

| Метод и путь | Доступ | Что делает |
|---|---|---|
| `GET /api/v1/monitors` | вход | Свои мониторы; пагинация `?page=&page_size=`, фильтры `?status=DOWN&status=PENDING`, `?is_active=`, `?is_public=` |
| `POST /api/v1/monitors` | вход | Создать монитор (валидация, SSRF по DNS, не больше 20). `201` / `422` |
| `GET /api/v1/monitors/{id}` | вход | Монитор. Чужой — `404` |
| `PUT /api/v1/monitors/{id}` | вход | Заменить все поля |
| `PATCH /api/v1/monitors/{id}` | вход | Изменить часть полей; `is_active` — пауза/возобновление |
| `DELETE /api/v1/monitors/{id}` | вход | Удалить вместе с историей. `204` |
| `GET /api/v1/monitors/{id}/checks` | вход | История проверок, новые первыми, с пагинацией; `?ok=false` — только неудачные |

### Статистика

| Метод и путь | Доступ | Что делает |
|---|---|---|
| `GET /api/v1/monitors/{id}/stats?period=24h\|7d\|30d` | вход | Uptime, среднее время ответа, p95, число инцидентов, временной ряд (шаг 15 мин / 1 ч / 6 ч). Кэш 1 / 5 / 15 мин |
| `GET /api/v1/monitors/summary` | вход | Сводка для дашборда по всем мониторам: последняя проверка, uptime за 24 ч, почасовой ряд. Кэш 15 с |

### Инциденты

| Метод и путь | Доступ | Что делает |
|---|---|---|
| `GET /api/v1/incidents` | вход | Инциденты своих мониторов; фильтры `?monitor=`, `?is_open=` |
| `GET /api/v1/incidents/{id}` | вход | Инцидент: начало, конец, длительность, причина |

Инциденты только читаются: открываются и закрываются проверками.

### Статус-страницы

| Метод и путь | Доступ | Что делает |
|---|---|---|
| `GET /api/v1/status-pages` | вход | Свои статус-страницы |
| `POST /api/v1/status-pages` | вход | Создать: название, `slug`, `monitor_ids` (свои мониторы). Не больше 5 |
| `GET /api/v1/status-pages/{id}` | вход | Страница |
| `PUT /api/v1/status-pages/{id}` | вход | Изменить |
| `DELETE /api/v1/status-pages/{id}` | вход | Удалить. `204` |
| `GET /api/v1/public/status-pages/{slug}` | все | Публичные данные страницы: название, общий статус, по каждому сервису — название, статус, uptime 24 ч / 30 дн. Без авторизации, 120 запросов/мин с IP, кэш 30 с |

### Полигон

| Метод и путь | Доступ | Что делает |
|---|---|---|
| `GET /api/v1/playground/targets` | вход | 8 тестовых эндпоинтов и их текущие режимы |
| `PATCH /api/v1/playground/targets/{slug}` | вход | Переключить режим: `{"mode": "error"}` |
| `GET\|HEAD\|POST /api/v1/playground/{slug}` | все | **Сам тестовый эндпоинт** — его вызывают мониторы. Поведение по режиму: `ok` (200 за 100 мс), `error` (500), `slow` (200 через 5–10 с), `hang` (молчит 75 с), `flapping` (~30% 503), `redirect-loop` (бесконечные 302), `huge-body` (50 МБ потоком), `wrong-content` (200 с HTML вместо JSON). 120 запросов/мин с IP |

### Служебные пути

| Путь | Что это |
|---|---|
| `GET /health` | Проверка PostgreSQL и Redis: `200` или `503`. Без авторизации, без редиректа на HTTPS |
| `/api/docs` | Swagger UI — интерактивная документация API (кнопка Authorize принимает access-токен) |
| `/api/schema` | Схема OpenAPI 3 |
| `/static/…` | Статика Django-админки и Swagger (whitenoise) |

## Django-админка — `/admin/`

Вход: `admin@pulse.app` / `AdminPulse2026!` — суперпользователь создаётся автоматически при старте
backend (`create_admin_user` в `deploy/entrypoint.sh`). Демо-аккаунт — обычный пользователь, в
админку не пускает. Адрес задаётся `ADMIN_PAGE_LOCATION` (по умолчанию `admin/`).

| Раздел | Путь | Что в нём |
|---|---|---|
| Users | `/admin/users/user/` | Пользователи: email, активен, сотрудник, дата регистрации; поиск по email |
| Monitors | `/admin/monitors/monitor/` | Все мониторы: владелец, URL, статус, флаги, последняя проверка; фильтры по статусу, методу, флагам |
| Check results | `/admin/checks/checkresult/` | История проверок (только просмотр): код, время ответа, причина; фильтр по успеху и коду ошибки, навигация по датам |
| Incidents | `/admin/incidents/incident/` | Инциденты: монитор, начало, конец, длительность, причина |
| Status pages | `/admin/status_pages/statuspage/` | Статус-страницы: адрес, название, владелец, выбранные мониторы |
| Playground targets | `/admin/playground/playgroundtarget/` | Эндпоинты полигона; режим меняется прямо в списке |
| Periodic tasks | `/admin/django_celery_beat/periodictask/` | Расписание Celery beat: `checks.dispatch_due_checks` (каждые 15 с), `checks.purge_old_checks` (раз в час) и связанные интервалы/crontab |
| Token blacklist | `/admin/token_blacklist/outstandingtoken/`, `…/blacklistedtoken/` | Выданные и отозванные refresh-токены |
| Groups | `/admin/auth/group/` | Стандартные группы Django |

## Фоновые процессы (без адреса)

| Что | Когда | Что делает |
|---|---|---|
| `checks.dispatch_due_checks` | Celery beat, каждые 15 с | Берёт мониторы, у которых подошла проверка (`FOR UPDATE SKIP LOCKED`), и ставит по задаче на монитор |
| `checks.run_check` | Celery worker | HTTP-проверка с таймаутом, лимитом редиректов и размера, SSRF-защитой; запись результата; смена статуса и открытие/закрытие инцидента |
| `checks.purge_old_checks` | Celery beat, раз в час | Удаляет историю старше 30 дней пачками по 5000 |
| `deploy/entrypoint.sh` | при старте backend | `migrate` → `create_demo_user` → `create_admin_user` → `seed_demo` → gunicorn |

Команды управления (`docker compose exec backend python manage.py …`): `create_demo_user`,
`create_admin_user`, `seed_demo`, `generate_check_history` (1 млн записей для нагрузочной проверки),
`explain_stats <monitor_id>` (EXPLAIN ANALYZE запросов статистики). Команды запуска стека —
`make` (список в корневом `Makefile`).
